# Работа над Кешбекером

Кешбекер подбирает банковскую карту по кешбеку. Текущий продукт — PWA на HTML, CSS и JavaScript без сборки.
GitHub Pages раздаёт интерфейс. Supabase отвечает за вход и синхронизацию. Скрипты имеют общий контекст браузера.

## Старт сессии и поиск

Начни с [текущего статуса](docs/STATUS.md), ветки, git status и документов по задаче.
1. Определи область задачи.
2. Найди модуль в [карте кода](docs/CODE_MAP.md).
3. Найди символ через `npm run code:find -- NAME`, `rg` или `git grep`.
4. Сверь номер строки с исходником. При устаревании регенерируй индекс.
5. Прочитай нужный диапазон исходника.
6. Проверь связанные вызовы, зависимости и тесты.
7. Расширяй поиск по мере необходимости.

Избегай полного чтения проекта, бинарников, node_modules и всех файлов индекса.
Используй исходник как источник поведения. Не перечитывай неизменившиеся файлы без причины.
Для детерминированных операций используй скрипты. Читай конкретные ошибки вместо больших успешных логов.

## Skills и специалисты

Загружай только относящиеся к задаче Skills из `.agents/skills`.
Один основной агент ведёт работу. Подключай специалиста при пользе для отдельной задачи.
Передавай границы задачи, файлы, ограничения и критерии приёмки. Разделяй области записи.
Используй отдельный контекст специалиста, если клиент позволяет выбрать режим запуска.
Делегирование одноуровневое. Основной агент проверяет результат и сводит изменения.
Уровень рассуждения по умолчанию medium. Повышай его для сложных задач.

## Git и безопасность

`main` — стабильная ветка, `develop` — ветка разработки.
Используй рабочие ветки `feature/*`, `fix/*`, `refactor/*`, `test/*`.
Сохраняй чужие изменения. Commit, push, merge и публикация требуют согласования.
Сохраняй sandbox. Запрещено менять production Supabase и автоматически развёртывать проект.
Не сохраняй данные платежей, реальные банковские скриншоты, секреты или ключ service_role в клиенте.
Тесты используют синтетические данные и изолированную сеть. Сохраняй PWA.

## Проверки и готовность

Запусти целевые тесты прежде общего `npm run check`. Для изменений пользовательского потока запусти E2E.
После изменения исходников обнови `npm run code:index` и проверь затронутые документы.
Перед завершением сверь критерии приёмки, покрытие тестами, git diff и отсутствие секретов.
Кратко перечисли проверки и известные проблемы. Запиши результат и следующую задачу в статус без логов.
